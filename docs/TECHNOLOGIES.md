# Soccerpoly · технологии и инженерные решения

В футбольной настольной игре Soccerpoly игрок выбирает между гарантированной наградой и ударом с риском потери. Инженерный кейс показывает, как дизайнер может изменить экономику сезонного события, получить проверяемый прогноз и передать одобренный каталог в игру. Continental Cup был выпущен в Roblox place v10. [Правила игры](GAME.md) · [Подтверждение выпуска](RELEASE.md)

## Инфраструктура, доступ и наблюдаемость

Две реплики Python/FastAPI работают в Kubernetes (kind) на стандартном Ubuntu-раннере GitHub Actions. На этом же раннере llama.cpp обслуживает два отдельных CPU-маршрута — Qwen2.5-0.5B-Instruct и SmolLM2-360M-Instruct. Шлюз направляет запрос на выбранную модель, а отдельный процесс игры обслуживает MCP по stdio. Код платформы общий для трёх игр. В каждом репозитории есть собственный MCP-адаптер и workflow. [Workflow этой игры](../.github/workflows/game-agents.yml) · [Шлюз на проверенной ревизии](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/gateway.py) · [Kubernetes-манифест](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/deployment.yaml)

- **Контекст и качество.** При запуске реплика читает ресурс с брифом игры. Для задания допускается до четырёх вариантов, размер сериализованного брифа ограничен 8 КиБ. Вывод модели ограничен JSON-схемой. Принятие решения принадлежит игровому инструменту. При отказе агент передаёт причину модели и исключает этот вариант из следующей попытки. [Контракт проекта](../scripts/agent_review.py)
- **Параллельные запросы и кеш.** В ключ входят игра, команда, ревизии игры и платформы, модель и отпечаток её весов, промпт и бриф. Транзакционная advisory-блокировка PostgreSQL 16 координирует запросы на разных репликах. Принимается только проверенный результат, срок действия — сутки. Ошибка до фиксации освобождает блокировку. Две тестовые команды используют отдельные bearer-токены. Запрос с неверным токеном получил 401.
- **Ревью и диагностика.** Ресурс MCP предоставляет информацию GitHub Actions о PR и ограниченный фрагмент кода из проверяемого git-коммита. Второй ресурс отдаёт записи SDK Sentry и Amplitude с локального приёмника на раннере. На контролируемый отказ записывается одно сообщение, на принятые решения — два события. Qwen получает фрагмент кода и отрицательный контроль и предлагает дополнительный тест. Ревью Qwen предположило отсутствие проверки гарантированной выплаты. Вызов validate и отрицательный контроль на 65 кредитов опровергают этот вывод. Это пример, когда ответ модели нужно сверить с кодом вызываемой функции. [Реализация](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/release_review.py) · [Ответ модели и данные SDK](evidence/cloud-review.json)

## Измеренный результат

Обе модели с первой попытки выбрали 84 кредита. Предложение на 65 кредитов было отклонено тем же правилом экономики, которое используется при сборке каталога. [Исходные запросы и ответы](evidence/cloud-review.json) · [Публичный прогон](https://github.com/GlebAvershin/Soccerpoly/actions/runs/44771393653)

| Серия одной тестовой команды | Клиентские запросы | Вызовы LLM | Токены inference | p95 у клиента |
| --- | ---: | ---: | ---: | ---: |
| Пустой кеш, обе модели уже загружены | 8 | 2 | 472 | 1664,33 мс |
| Повтор | 8 | 0 | 0 | 34,06 мс |
| После замены обоих pod | 8 | 0 | 0 | 41,85 мс |

В каждой серии четыре запроса направлены к каждой модели, трафик разделён между двумя репликами. В первой серии шесть запросов переиспользовали результаты соседних запросов. Та же задача для второй команды дала отдельный промах. После rolling restart проверены новые имена обоих pod и сохранность результатов для каждой команды. Таблица включает токены всех попыток **первой команды** для игрового задания. Отдельный обзор PR, контрольный запрос второй команды и подготовка инфраструктуры в неё не входят. На восьми запросах p95 по методу ближайшего ранга совпадает с максимумом. Это короткий функциональный нагрузочный тест.

В нём есть ответы до и после перезапуска, события SDK и текст ревью. Прогон работает также при открытии PR. Постоянный сервис и платный аккаунт модели для проверки не требуются. ## Проверка через подписки разработчика

Каждая модель выбрала минимальную экономически допустимую выплату из трёх вариантов. Валидатор затем проверил её на действующем каталоге Continental Cup. Один и тот же MCP-бриф передан Codex CLI через вход ChatGPT и Gemini через Google Antigravity CLI. Обе команды запущены на Mac. Инференс выполняли сервисы провайдеров.

| Маршрут | Запрошенная модель | Выбор | Вердикт игрового инструмента |
| --- | --- | --- | --- |
| Codex | gpt-6.2-sol | `offer_84` | Принято |
| Google Antigravity | gemini-3.8-flash-low | `offer_84` | Принято |

В протоколе сохранены обоснования моделей, версия исходников, хеш брифа и независимые вердикты. Это по одному завершённому решению на маршрут. Скрипт использует локальные сеансы CLI, для Gemini отключает расход дополнительных AI-кредитов и передаёт ответы существующему MCP-инструменту. Облачный нагрузочный тест выше использует отдельные серверы Qwen и SmolLM2.
