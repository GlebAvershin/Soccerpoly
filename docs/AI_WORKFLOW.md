# Создание игрового события с AI

Реальный пример в репозитории — «Кубок континентов». Codex проверил референс и вакансии, предложил механику, написал черновик каталога и реализацию, запустил проверку, исправил сценарий теста и подготовил аналитический разбор. На собеседовании полезно обсудить конкретный выбор весов и проверку, которая предотвращает дисбаланс.

## Из брифа в сборку

1. Сформулировать сюжет, ограничения по источникам, лимит карточек и правила экономики. Текущий бриф просит гол, офсайд, штраф и кубок на матче.
2. `python3 scripts/event_studio.py prompt` выдаёт задание и актуальную схему. Для агента через MCP запустить `uv run scripts/event_context_mcp.py` по stdio. Ресурс хранит формат каталога. Инструменты возвращают расчёт и проверяют предложенный JSON.
3. Черновик сохраняется отдельно. `python3 scripts/draft_event.py --from-response draft.json --output .tools/reviewed-draft.json` проверяет результат и создаёт новый файл только при валидном ответе. В режиме провайдера передаются `--provider bedrock|databricks --model NAME --brief brief.txt`. Для Bedrock нужен `boto3` и AWS permissions. Для Databricks нужен существующий endpoint и переменные `DATABRICKS_HOST`, `DATABRICKS_TOKEN`. Запросы отправляются только при явном запуске режима провайдера. [Amazon Bedrock Converse](https://docs.aws.amazon.com/boto3/latest/reference/services/bedrock-runtime/client/converse.html) · [Databricks Model Serving](https://docs.databricks.com/aws/en/machine-learning/model-serving/score-model-serving-endpoints).
4. После проверки текста, источников и результатов перенести JSON в `content/continental-cup.json` и выполнить `python3 scripts/event_studio.py compile`. Валидатор ограничивает вероятность гола, цены и размер эффекта. Гарантированный доход остаётся между ожидаемыми кредитами за удар и итоговой стоимостью удара с кубком.
5. `make verify` сверяет сгенерированный каталог, компилирует Luau, прогоняет сценарии и повторяет расчёт в независимом C++ inspector. Studio проверяет действие через настоящий RemoteEvent и наличие HUD, модели кубка и корректного финала.
6. Перед запуском в облаке проверить возрастной охват, доступ и подготовить предыдущую сборку к откату. Проверка статистики имеет отдельную точку принятия решения. [Публикация](RELEASE.md) · [Эксперимент](ANALYTICS.md).
