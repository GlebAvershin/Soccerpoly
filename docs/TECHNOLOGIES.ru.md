В футбольной настольной игре Soccerpoly игрок выбирает между гарантированной наградой и ударом с риском потери. Инженерный кейс показывает, как дизайнер может изменить экономику сезонного события, получить проверяемый прогноз и передать одобренный каталог в игру. Continental Cup был выпущен в Roblox place v10. [Играть в Roblox](https://www.roblox.com/games/114770772027261/Soccerpoly-Continental-Cup) · [Разбор события](CONTINENTAL-CUP.md) · [Правила игры](GAME.md) · [Подтверждение выпуска](RELEASE.md)

## Когда советовать удар

Для Continental Cup проверили каждую целую сумму, которой игроку может не хватать до покупки за один ход, от 1 до 141 кредита. При нехватке 1–75 кредитов гарантированная награда всегда покрывает цель. При 76–140 кредитах только удар даёт шанс на покупку (3 из 6 по сумме весов, 50%). При нехватке 141 кредита покупку приходится отложить. Для каждой суммы сверили и действие, и вероятность с функцией `recommend_cash` в Event Studio.

Расчёт выполнил инструмент `aws___run_script` управляемого MCP-сервера AWS через Agent Toolkit for AWS в Codex. На момент запуска действовал план AWS Free. Сервис вернул успешный результат с нулём обращений к API ресурсов. [Результат и контрольные суммы](evidence/aws-toolkit.json) · [Расчёт и проверка](../studio/research/aws_audit.py) · [Как повторить](https://github.com/GlebAvershin/lantern-atlas/blob/main/studio/research/README.md#aws-agent-toolkit-replay)

## Рекомендация для одного решения Continental Cup

Инструмент Event Studio отвечает на вопрос «Сколько наличных не хватает для покупки и каким действием их можно получить за один ход?». Он перечисляет исходы броска по весам действующих правил и сравнивает шанс покрыть недостачу с гарантированной выплатой. При равных положительных шансах выбирает гарантию. Если оба шанса равны нулю, предлагает отложить покупку. Стоимость трофея в эту цель не входит.

| Не хватает кредитов | Совет | Шанс покрыть недостачу выбранным действием |
| ---: | --- | ---: |
| 75 | Взять гарантированную выплату | 100% |
| 76 | Бросить | 50% |
| 140 | Бросить | 50% |
| 141 | Отложить покупку | Ни один вариант выплаты не покрывает цель |

Решение доступно через MCP-инструмент `recommend_cup_action(target)` и через CLI. Обе точки входа вызывают один расчёт. Проверка через MCP перебрала все положительные цели до максимального выигрыша плюс один кредит. Все 141 рекомендации и их шансы совпали с независимым перебором исходов. [Проверка по всему диапазону](evidence/recommendation-check.json) · [Реализация](../scripts/event_studio.py)

```sh
python3 scripts/event_studio.py recommend --target 76
```

В предыдущем исследовании Qwen правильно ответила на 1 из 4 граничных случаев после уточнения контекста. Теперь запрос получает числители шансов обеих стратегий с общим знаменателем. В AWS Bedrock модель вернула точную команду **4/4** в первом прогоне и **4/4** при повторе с дробями. Продуктовый инструмент рассчитывает решение непосредственно по каталогу. [Первый эксперимент](https://github.com/GlebAvershin/Soccerpoly/blob/ffdd040/docs/TECHNOLOGIES.md) · [Повтор с моделью](evidence/research-paired.json)

Databricks SQL и SQLite вернули одинаковые показатели. Amplitude приняла события проверки (4), Sentry — предупреждения о контролях или расхождениях (1). [Трасса и квитанции](evidence/research.json) · [История запроса Databricks](evidence/research-sql.json)

## Что делает облачный агент

Обе модели получают веса исходов, текущий гарантированный платёж и границы ожидаемой ценности. В задании дизайнера три альтернативы — 65, 84 и 95 кредитов. Нужно выбрать наименьшую допустимую. MCP-инструмент подставляет предложение в копию исходного каталога и запускает валидатор сборки. 65 нарушает правило баланса, 95 проходит его, а 84 проходит и дополнительное требование дизайнера. В опубликованном игровом каталоге остаётся исходное значение 75. Шлюз направляет запрос на выбранную модель, а отдельный процесс игры обслуживает MCP по stdio. Код платформы общий для трёх игр. В каждом репозитории есть собственный MCP-адаптер и workflow. - **Контекст и качество.** При запуске реплика читает ресурс с брифом игры. Для задания допускается до четырёх вариантов, размер сериализованного брифа ограничен 8 КиБ. Вывод модели ограничен JSON-схемой. Принятие решения принадлежит игровому инструменту. При отказе агент передаёт причину модели и исключает этот вариант из следующей попытки. [Контракт проекта](../scripts/agent_review.py)
- **Параллельные запросы и кеш.** В ключ входят игра, команда, ревизии игры и платформы, модель и отпечаток её весов, промпт и бриф. Транзакционная advisory-блокировка PostgreSQL 16 координирует запросы на разных репликах. Принимается только проверенный результат, срок действия — сутки. Ошибка до фиксации освобождает блокировку. Две тестовые команды используют отдельные bearer-токены. Запрос с неверным токеном получил 401.
- **Ревью и диагностика.** Ресурс MCP предоставляет информацию GitHub Actions о PR и ограниченный фрагмент кода из проверяемого git-коммита. Второй ресурс отдаёт записи SDK Sentry и Amplitude с локального приёмника на раннере. На контролируемый отказ записывается одно сообщение, на принятые решения — два события. Qwen получает фрагмент кода и отрицательный контроль и предлагает дополнительный тест. Ревью Qwen предположило отсутствие проверки гарантированной выплаты. Вызов validate и отрицательный контроль на 65 кредитов опровергают этот вывод. Это пример, когда ответ модели нужно сверить с кодом вызываемой функции. [Реализация](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/release_review.py) · [Ответ модели и данные SDK](evidence/cloud-review.json)

## Автоматическая генерация LiveOps «Champions Derby» и стресс-тест экономики на 100 000 матчей

Для поддержки регулярного цикла сезонных событий (LiveOps) разработана сквозная система генерации и аудита игровых ивентов, связывающая генеративные модели Databricks, строгую C++17 валидацию инвариантов и симулятор макроэкономики на 100 000 матчей.

### Автоматический синтез события и проверка инвариантов

В `scripts/ai_event_author.py` реализован многошаговый пайплайн генерации двуязычного события **«Champions Derby» (Дерби чемпионов)**:
1. Модель формирует схему карточек и исходов ударов.
2. Встроенный валидатор `event_studio.py` математически проверяет, что шанс гола не превышает 50%, а гарантированная выплата (80 CR) строго ограничена интервалом $[\text{Expected Cash}, \text{Expected Portfolio Value}]$.
3. Нативный инспектор `native/cup_preview.cpp` на C++17 подтверждает вероятности исходов и формирует растровое распределение в `dist/analytics/cup-odds.ppm`.

| Параметр баланса | Continental Cup v1 | Champions Derby v1 (Новый LiveOps) | Статус инварианта |
| :--- | :---: | :---: | :---: |
| Шанс забить гол (Goal Odds) | 50.0% (вес 3 из 6) | 50.0% (вес 3 из 6) | $\le 50.0\%$ (Соблюдён) |
| Ожидаемая выплата удара (EV Cash) | 71.67 CR | 79.17 CR | Расчёт C++17 подтверждён |
| Полная ценность с трофеем (EV Portfolio) | 111.67 CR | 124.17 CR | Трофей 90 CR учтён |
| Гарантия без риска (Safe Cash) | 75 CR | 80 CR | $79.17 \le 80 \le 124.17$ (Соблюдён) |
| Состав колоды карточек | 11 карт | 6 карт (фол, гол, премия, скаут, скамейка, VAR) | Все обязательные типы покрыты |

Для исключения гиперинфляции игровой валюты за 14-дневный сезонный цикл симулятор `scripts/simulate_economy.py` воспроизвел 100 000 турнирных матчей для 10 000 независимых игроков с учетом трат на взносы (Entry Fee), тактические рероллы и покупку трофеев.

### Мультиагентный совет рецензентов (LLM-as-a-Judge Consensus)

В `scripts/multi_agent_judge.py` развернута система автоматического аудита новых событий тремя специализированными персонами-агентами на базе `databricks-qwen3-next-80b-a3b-instruct`:
1. **Chief Game Economy Auditor:** оценивает риск гиперинфляции и математические инварианты.
2. **Player Experience & UX Director:** анализирует прозрачность правил, эмоциональный ритм и риск фрустрации от поражений.
3. **LiveOps & Retention Lead:** проверяет ценность трофеев и потенциал долгосрочного удержания.

По результатам рецензирования формируется взвешенный индекс **Production Performance Readiness Score (PPRS 0–100)**:
* **Критический инсайт агентов:** Оба события (`Continental Cup` с PPRS 52.0 и `Champions Derby` с PPRS 58.0) получили статус `NEEDS_REVISION` из-за штрафа за офсайд (-35 и -40 CR). Агенты единогласно отметили, что резкий отъем валюты при низком весе (1 из 6) демотивирует казуальных игроков, и рекомендовали заменить отрицательные выплаты на механику «сгорания бонуса серии» без прямого списания с баланса.
