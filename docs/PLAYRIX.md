| Вероятность, статистика и план A/B | Постоянное назначение по игроку, ITT, размер выборки, SRM, интервалы Newcombe, основная метрика и ограничение по завершению сезона. Вывод на 3 600 синтетических назначениях отражает непрохождение ограничения |
| SQL, Python, Jupyter | Запросы SQL с оконной функцией для первого назначения, Python ETL, тест граничного случая, исполненный Jupyter notebook. Результат воспроизводится с теми же входными данными |
| Databricks, PySpark и Parquet | Скрипт сравнивает результат Spark с SQL и пишет витрину в Parquet. Databricks workspace требует доступ. Локальный Spark 4.0.1 подтвердил совпадение для всех пяти размеров стола и записал Parquet |
| Airflow, S3, Redshift, Monte Carlo | Airflow DAG для запуска ETL, DDL и COPY для Redshift из S3, хеш и lineage в артефактах, валидация событий и дрейфа назначения. Развёртывание AWS и Monte Carlo остаётся отдельным подключением |
| AppsFlyer и Amplitude | Витрина принимает нормализованные event и channel. В тестовых данных каналы заданы симуляцией. Связка маркетингового ID и игровых событий требует разрешённого реального источника и согласованного идентификатора |
| Tableau, повторяемые отчёты и self-service | CSV для Tableau, интерактивный HTML-дашборд с переключением сегментов и ноутбук. В Tableau workbook не проверяли |
| Аналитика продукта и маркетинга с реальными данными | Источники рынка и план закрытого теста доступны. Удержание, рекламные затраты, расценки и производительность в облаке появятся после измерений |

## Демонстрация

1. За инженерную роль покажи выбор маршрута и удар на Matchday. Открой ключи бега в Blender и покажи, как Python передаёт их в Luau. Затем измени вес результата в отдельной копии JSON и покажи ошибку валидатора, расчёт через C++ и график OpenGL.
2. За аналитическую роль открой отчёт с разбивкой по устройству. Объясни, почему при +8,89 п.п. по активации эксперимент ещё не проходит ограничение по завершению и как изменится размер выборки при другой допустимой просадке.
3. В конце сравни экономику стола на двоих и на шестерых. При шести местах в симуляции игрок в среднем владеет 1,88 клуба против 3,47 на двоих. Это основание наблюдать за доступностью контрактов в живой игре. [Аналитический протокол](ANALYTICS.md)
