# Сколько времени занимает правка экономики Continental Cup

**Вопрос исследования.** Насколько агент помогает другому разработчику получить принимаемый каталог? Участник получает два задания одинакового типа. Нужно пересчитать гарантированную выплату после изменения награды за гол, выбрать минимальную допустимую сумму и сохранить остальное содержимое каталога. Исход эксперимента — принятый игровой каталог, который проходит валидатор сборки и проверку брифа.

**Статус.** Подготовлен протокол для 2–3 независимых разработчиков. Участники ещё не проходили задания. Автоматическая репетиция проверяет механику исследования. [Запись репетиции](evidence/cup-trial-smoke.json)

## Подготовка ведущего

Нужны Python 3 и локальный llama.cpp с Qwen2.5-0.5B-Instruct GGUF, alias `qwen`, на порту 18181. Участник может работать на стенде ведущего. Подготовьте один и тот же редактор, прогрейте модель отдельным запросом до начала измерений и закройте историю предыдущих участников. Запишите коммит проекта, версию модели и среду. Вся работа проходит в копиях каталога. [Модель и контрольная сумма](https://github.com/GlebAvershin/lantern-atlas/blob/main/studio/agents/cloud.sh) · [Код упражнения](../scripts/cup_trial.py)

## Прохождение

Из корня Soccerpoly создайте новую папку **вне репозитория**. Порядковый номер участника назначается до начала сессии. Номера 1–4 чередуют порядок заданий A/B и условия ручной/агент. Обоим заданиям отведите одинаковый предел времени, например десять минут. Зафиксируйте незавершённую задачу при истечении времени.

```sh
session=/tmp/cup-participant-01
python3 scripts/cup_trial.py init "$session" --number 1 --source human
python3 scripts/cup_trial.py start "$session"
```

Таймер запускается при показе текста задания. В ручном режиме участник редактирует указанный файл в обычном редакторе и выполняет `python3 scripts/cup_trial.py submit "$session"`. В режиме агента выполните `python3 scripts/cup_trial.py assist "$session"`, откройте предложенный JSON и проверьте его. Инструмент покажет вердикт. При повторном вызове модель получит причину отказа и оставшиеся варианты. Для принятия предложения выполните `submit "$session" --suggested`. Для исправления можно скопировать поля в рабочий черновик и выполнить обычный `submit`. Каждая отклонённая отправка и её причина сохраняются. После приёмки запустите `start` ещё раз для второго задания.

## Наблюдение, правка и повтор

До старта следующего задания ведущий выполняет `python3 scripts/cup_trial.py note "$session" --edits 1 --text "…"` с фактическим числом правок и обезличенным наблюдением. Для выгрузки индивидуальных результатов выполните `python3 scripts/cup_trial.py summary /tmp/cup-participant-01 /tmp/cup-participant-02`. Сводка пропускает репетиции, сохраняет незавершённые раунды и показывает разность только для полных пар.

Ведущий сохраняет в локальной папке сессии номер коммита, трудное место, наблюдаемое действие, дословное замечание с согласия участника и число ручных правок в каждом режиме. Сценарий записывает время, запросы к модели, отказы валидатора и финальные каталоги. После двух задач попросите участника показать момент, когда ему потребовалась помощь.

Для каждого участника покажите **обе** длительности, разность «вручную минус с агентом», число исправлений и причины отказов. Незавершённые задания оставляйте видимыми. При двух-трёх участниках описывайте индивидуальные результаты и эффект порядка.

Выберите одно повторяемое затруднение. Запишите наблюдение и ожидаемый результат до исправления, свяжите изменение с коммитом и попросите участника пройти сопоставимое новое задание. При повторном использовании знакомого задания отметьте эффект обучения. Публиковать можно обезличенные итоги с согласия участника. Сессии `smoke` относятся к техническим проверкам.

## Что исправила техническая репетиция

При первом прогоне Qwen предложила для A выплату 85, для B — 100. Оба предложения прошли базовую экономическую проверку, но нарушили требование выбрать минимальную выплату. В первой версии участник узнавал причину только при отправке. После правки инструмент показывает вердикт сразу и возвращает модели причину при повторном запросе. При повторной репетиции обе задачи получили верный ответ с третьей попытки — 70 для A и 90 для B. Это проверка контура исправления при ограниченном выборе. Влияние на время работы человека ещё предстоит измерить. [Оба прогона](evidence/cup-trial-smoke.json)
